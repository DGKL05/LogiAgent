# LogiAgent 开发文档

## 当前阶段

Milestone 3 聚焦 AI Agent MVP：

```text
用户自然语言提问 -> Agent 识别意图 -> Tool 调用运单和轨迹服务 -> 规则分析 -> 返回自然语言诊断
```

本阶段实现规则版 Agent，不接入真实大模型，不实现路线规划、调度服务、RabbitMQ、Seata、Sentinel、Elasticsearch、复杂 RAG 和前端页面。

## 开发原则

- Agent 不直接访问 order、waybill、track 数据库。
- Agent 通过 Tool 调用 Feign Client。
- Tool 返回 DTO，不返回 Entity。
- Tool 成功和失败都记录调用日志。
- Controller 只接收参数和返回 `Result<T>`。
- DTO、Request、Feign Client 继续放在 `logistics-api`。

## logistics-ai-agent-service 结构

- `controller`：Agent HTTP 接口。
- `core`：`SupervisorAgent`、`WaybillQueryAgent`、`ExceptionDiagnosisAgent`、`AgentIntentClassifier`。
- `tool`：`WaybillTool`、`TrackTool`。
- `service`：会话、Tool 日志、聊天编排服务。
- `entity` / `mapper`：Agent 会话和 Tool 日志表映射。
- `config`：MyBatis Plus 配置和 Spring AI API Key 占位配置。
- `llm`：`LlmAnswerService` 预留后续大模型增强入口。

## Agent 意图

当前支持：

- `WAYBILL_QUERY`：运单查询。
- `WAYBILL_EXCEPTION_DIAGNOSIS`：运单异常诊断。
- `UNKNOWN`：无法识别或缺少运单号。

规则：

- 包含“为什么”“异常”“没签收”“未签收”“不更新”“分析”时，识别为异常诊断。
- 包含 `WB...` 运单号且无异常关键词时，识别为运单查询。

## Tool 调用链路

```text
SupervisorAgent
  -> ExceptionDiagnosisAgent / WaybillQueryAgent
  -> WaybillTool / TrackTool
  -> WaybillFeignClient / TrackFeignClient
  -> logistics-waybill-service / logistics-track-service
```

## Milestone 4 路线规划双模式

`logistics-route-service` 负责路线规划，核心原则是百度地图只作为可选增强，不替代本地算法。

### 设计

- `LOCAL_DIJKSTRA`：读取 `t_station` 和 `t_route`，按策略选择权重并执行 Dijkstra。该模式是默认 provider，也是所有外部调用失败时的兜底。
- `BAIDU_DRIVING`：调用百度地图轻量级驾车路线规划 API。调用前会检查 `baidu.map.enabled`、`BAIDU_MAP_AK`、起终点经纬度和途经点数量。
- Fallback：百度未启用、AK 为空、坐标缺失、请求异常、超时、返回 `status != 0` 或无路线时，自动调用 `LOCAL_DIJKSTRA`，并在响应中设置 `fallbackUsed`、`fallbackReason`。

### 关键类

- `RoutePlanner`：路线规划策略接口。
- `LocalDijkstraRoutePlanner`：本地 Dijkstra 实现。
- `BaiduDrivingRoutePlanner`：百度驾车路线实现和 fallback 编排。
- `BaiduMapRouteClient`：百度 API HTTP 客户端。
- `RoutePlannerFactory`：根据 `RoutePlanRequest.provider` 选择 planner。
- `RouteTool` / `RoutePlanningAgent`：Agent 通过 Feign 调用 route-service，不直接访问路线数据库。

### 策略映射

百度 `tactics` 映射：

- `TIME_FIRST` / `BALANCED` -> `0`
- `AVOID_HIGHWAY` -> `1`
- `AVOID_TRAFFIC` -> `2`
- `DISTANCE_FIRST` -> `3`
- `COST_FIRST` -> `4`
- `HIGHWAY_FIRST` -> `5`
- `AVOID_FERRY` -> `6`

## Milestone 4 调度建议与物流日报

### dispatch-service

`logistics-dispatch-service` 只管理自己的 `t_dispatch_task` 表，不直接访问订单、运单、轨迹或路线服务数据库。

核心类：

- `DispatchController`：暴露派件任务、网点负载和调度建议接口。
- `DispatchServiceImpl`：创建任务、查询任务、计算负载排行、生成建议。
- `StationLoadLevelPolicy`：封装负载等级规则。

负载等级规则：

- `LOW`：待处理任务数小于 20。
- `MEDIUM`：待处理任务数 20 - 49。
- `HIGH`：待处理任务数 50 - 99。
- `OVERLOAD`：待处理任务数大于等于 100，或异常件数量较高。

### Agent

新增：

- `DispatchSuggestAgent`
- `LogisticsReportAgent`
- `DispatchTool`
- `ReportDataTool`

意图识别：

- `DISPATCH_SUGGESTION`：包含“调度”“压力最大”“网点压力”“负载”“派件压力”“哪个网点忙”“任务最多”“异常件最多”等关键词。
- `DAILY_REPORT`：包含“日报”“物流日报”“生成报告”“今天统计”“运营报告”“今日概况”等关键词。

日报是 Markdown 格式，通过 Tool 调用订单、运单和调度服务。当前 MVP 缺少运单按日期统计、签收统计、轨迹按日期统计接口，这些字段在日报中明确标注为暂未统计。
## Milestone 5 真实统计日报

Milestone 5 的目标是补齐 order、waybill、track 三个业务服务的统计接口，并让 `LogisticsReportAgent` 通过 `ReportDataTool` 调用 Feign Client 获取真实数据。

### 服务边界

- `logistics-order-service` 只统计 `t_order`。
- `logistics-waybill-service` 只统计 `t_waybill`。
- `logistics-track-service` 只统计 `t_track`。
- `logistics-ai-agent-service` 不直接访问业务数据库，只通过 `ReportDataTool -> Feign Client -> 业务服务` 获取统计。

### 新增统计 DTO

- `OrderDailyStatisticsDTO`
- `WaybillDailyStatisticsDTO`
- `TrackDailyStatisticsDTO`
- `LogisticsDailyReportDTO`

### 统计与容错

- 订单新增数使用 `t_order.create_time`。
- 运单新增数使用 `t_waybill.create_time`。
- 已签收数量使用当前 `current_status=SIGNED` 且 `update_time` 位于统计区间。
- 异常件数量使用当前 `current_status=EXCEPTION`，这是 MVP 当前风险口径。
- 轨迹统计优先使用 `t_track.event_time`，为空时 fallback 到 `create_time`。
- `ReportDataTool` 每次统计调用都会写入 `t_agent_tool_log`。如果某项调用失败，`LogisticsReportAgent` 会捕获异常，并在 Markdown 日报中显示“该项数据暂不可用”，不会使用假数据。
