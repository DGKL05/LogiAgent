# LogiAgent 数据库设计

## 初始化脚本

```text
docs/sql/init-logistics-core.sql
```

PowerShell 初始化：

```powershell
$env:MYSQL_PWD=$env:MySQLPASS
Get-Content -Raw docs/sql/init-logistics-core.sql | mysql -h 127.0.0.1 -P 3306 -u root
```

## 核心业务表

### t_order

订单表，归属 `logistics-order-service`。

字段：`id`、`order_no`、`sender_id`、`receiver_name`、`receiver_phone`、`receiver_address`、`goods_name`、`weight`、`status`、`create_time`、`update_time`。

### t_waybill

运单表，归属 `logistics-waybill-service`。

字段：`id`、`waybill_no`、`order_no`、`current_status`、`exception_type`、`exception_reason`、`create_time`、`update_time`。

### t_track

轨迹表，归属 `logistics-track-service`。

字段：`id`、`waybill_no`、`action`、`description`、`operator_id`、`event_time`、`create_time`。

索引：`idx_track_waybill_time (waybill_no, event_time)`。

## Agent 表

### t_agent_session

Agent 会话表，归属 `logistics-ai-agent-service`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键 |
| session_id | VARCHAR(40) | Agent 会话号，唯一 |
| user_id | BIGINT | 用户 ID，可为空 |
| question | VARCHAR(512) | 用户问题 |
| intent | VARCHAR(64) | 识别出的意图 |
| answer | TEXT | Agent 回答 |
| create_time | DATETIME | 创建时间 |

### t_agent_tool_log

Agent Tool 调用日志表，归属 `logistics-ai-agent-service`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键 |
| session_id | VARCHAR(40) | Agent 会话号 |
| tool_name | VARCHAR(128) | Tool 方法名 |
| request_params | TEXT | 请求参数 |
| response_result | TEXT | 响应摘要 |
| success | TINYINT(1) | 是否成功 |
| error_msg | TEXT | 错误信息 |
| cost_ms | BIGINT | 耗时毫秒 |
| create_time | DATETIME | 创建时间 |
## 路线规划表

### t_station

网点表，用于本地 Dijkstra 和百度地图坐标组装。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键 |
| `station_name` | VARCHAR(64) | 网点名称 |
| `city` | VARCHAR(64) | 城市 |
| `address` | VARCHAR(255) | 地址 |
| `longitude` | DECIMAL(10,6) | 经度 |
| `latitude` | DECIMAL(10,6) | 纬度 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

调用百度地图 API 时必须按 `latitude,longitude` 组装，即“纬度,经度”，不能写反。

### t_route

线路表，用于本地 Dijkstra。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键 |
| `start_station_id` | BIGINT | 起点网点 ID |
| `end_station_id` | BIGINT | 终点网点 ID |
| `distance_km` | DECIMAL(10,2) | 距离，公里 |
| `duration_minute` | DECIMAL(10,2) | 预计耗时，分钟 |
| `cost` | DECIMAL(10,2) | 运输成本，元 |
| `enabled` | TINYINT(1) | 是否启用 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

初始化脚本 `docs/sql/init-logistics-core.sql` 已包含广州网点、深圳网点、东莞中转站、佛山网点及示例线路。

## 调度表

### t_dispatch_task

派件任务表，归属 `logistics-dispatch-service`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键，自增 |
| `task_no` | VARCHAR(64) | 派件任务号，唯一 |
| `waybill_no` | VARCHAR(64) | 运单号 |
| `courier_id` | BIGINT | 快递员 ID |
| `station_id` | BIGINT | 网点 ID |
| `task_status` | VARCHAR(32) | 任务状态 |
| `assign_time` | DATETIME | 分配时间 |
| `finish_time` | DATETIME | 完成时间 |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |

任务状态：

- `CREATED`
- `ASSIGNED`
- `DELIVERING`
- `FINISHED`
- `CANCELLED`

初始化脚本包含少量测试派件任务，用于验证网点负载排行和调度建议。
## Milestone 5 统计口径

本阶段没有新增数据表，也没有修改现有字段，优先复用已有时间和状态字段。

### 订单统计

- `totalOrderCount`：`t_order` 全表数量。
- `newOrderCount`：`t_order.create_time` 位于统计区间。
- `cancelledOrderCount`：当前 `status = CANCELLED` 且 `update_time` 位于统计区间。
- `orderStatusCountMap`：当前订单状态分布。

### 运单统计

- `totalWaybillCount`：`t_waybill` 全表数量。
- `newWaybillCount`：`t_waybill.create_time` 位于统计区间。
- `signedWaybillCount`：当前 `current_status = SIGNED` 且 `update_time` 位于统计区间。
- `exceptionWaybillCount`：当前 `current_status = EXCEPTION` 的运单数量。
- `transportingWaybillCount`：当前 `current_status = TRANSPORTING` 的运单数量。
- `waybillStatusCountMap`：当前状态分布。
- `exceptionTypeCountMap`：当前异常类型分布。

### 轨迹统计

- `trackUpdateCount`：优先使用 `t_track.event_time`，为空时使用 `create_time`。
- `activeWaybillCount`：统计日期内有轨迹更新的去重运单数。
- `actionCountMap`：统计日期内轨迹动作分布。
- `latestTrackUpdateTime`：统计结果中的最大业务时间。
## Milestone 6 数据库变化

本阶段未新增数据表。为支持管理后台网点筛选和逻辑禁用，`t_station` 增加：

- `province VARCHAR(64) NULL`
- `status VARCHAR(32) NOT NULL DEFAULT 'ENABLED'`

线路管理继续复用 `t_route.enabled` 字段。禁用线路时只更新 `enabled=false`，不物理删除数据；Dijkstra 路线规划仍只读取启用线路。
